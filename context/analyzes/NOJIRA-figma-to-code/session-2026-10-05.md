## The two things I did that the audits caught

**I quietly replaced the metadata contract.** `A-NOJIRA-figma-metadata-contract` has 36 numbered
requirements, a three-artifact split and a six-case acceptance test. Its `Leads to` names a plan
and an ADR that were never created. Four days later I approved a plan whose task 00 is "the
contract itself" and **cited one of the thirty-six**. Fixed: the R-list is now task 00's primary
input and its first deliverable is a disposition against every one.

**`ARCH-handover-package` specifies the same artifact as the common format**, under another name,
and neither referenced the other. Fixed: the plan is authoritative, and what survives from the
architecture document — **layout intent and bound variables** — is folded in.

The pattern in both: **a new plan reads the analyses and not the architecture, and nothing makes
it.** The mechanical defence proposed: a plan cannot be approved without a disposition against
its `source_analysis`'s numbered requirements.

## Method lessons, which generalise past this project

- **A broken measurement tool does not raise; it returns a number.** Six of mine did.
- **A check must be able to prove it looked** — report what was examined, not only what was found.
- **Agreement across runs is evidence about a symptom, never about its cause.** Four runs agreed
  on serif text and produced a confident wrong diagnosis; one measurement overturned it.
- **Quiet replacement does not announce itself.** A contradiction shows up when two documents are
  read together; a re-derivation reads as perfectly coherent because it is — merely smaller.
- **A gate nobody can pass is not a gate.** It converts a check into an obstacle, and clearing
  the obstacle is where variance enters.
