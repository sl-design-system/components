# `.sl-ds-config.yaml` Template

> **Purpose:** Reference template used by `/sl-ds-setup` Step 4 when writing a fresh config. Pre-existing config keys are preserved on merge; only template defaults get filled in for missing keys.

## Source

Adapted from the existing `.agents/.sl-ds-config.yaml` (commit history) with simplifications. The template documents every key with inline comments so users editing the file know what each does.

## Template

```yaml
# Sanoma Learning DS — Project Configuration
# Generated by /sl-ds-setup. Safe to edit by hand; comments explain each key.
# Re-run /sl-ds-setup --reset to regenerate.

sl-ds-agents:
  version: "1.0"                          # Schema version — bump when /sl-ds-setup changes the shape

  framework: "<detected>"                  # angular | react | vue
  slds_version: "<detected>"               # SLDS version; omit if not installed (custom mode)

  project:
    root: "<repo-root>"                    # Repo root (usually ".")
    nx_enabled: <true|false>               # Detected from nx.json
    theme: "sanoma-learning"               # SLDS theme (default for Sanoma)
    target_scope: "<detected>"             # apps/<name> or libs/<name> — where DS code lives

  pipeline:
    mode: "automatic"                      # automatic | approval — pipeline.mode=approval pauses between major steps
    confidence_threshold: 40               # 0-100; below this, pipeline pauses for user review
    max_repair_cycles: 3                   # Max auto-repair attempts per failure
    repair_token_budget: 30000             # Token cap per repair loop
    wip_commits: true                      # Create WIP commits after each major step
    commit_prefix: "wip(sl-ds)"               # Prefix for WIP commit messages

  quality:
    composite_threshold: 95                # Minimum weighted composite score (0-100)
    floor_threshold: 90                    # Minimum per-group floor score
    groups:
      architecture: { weight: 22, floor: 90 }
      code_quality: { weight: 23, floor: 90 }
      visual_fidelity: { weight: 25, floor: 90 }
      accessibility: { weight: 18, floor: 90 }
      ds_maintainability: { weight: 12, floor: 90 }

  prototype:
    default_mode: "A"                      # A = HTML prototype, B = Angular prototype
    angular_variant: "B2"                  # B1 = CDN demo, B2 = full Angular project

  accessibility:
    standard: "WCAG22-AA"                  # WCAG version + level
    additional: []                         # Extra standards e.g. ["EN-301-549"]
    agents:
      a11y-audit:
        fail_on: "critical"
        report_format: "markdown"
      a11y-impl:
        auto_fix: true
        patterns: "<detected-framework>"
      a11y-test:
        include_manual: true
        device_matrix:
          - "VoiceOver+Safari"
          - "NVDA+Chrome"
          - "TalkBack+Android"

  cache:
    directory: ".sl-ds-cache"                 # Where machine-state lives — must be gitignored
    log_retention: 10                      # Number of historical run logs to keep
    figma_ttl: 0                           # 0 = use lastModified, >0 = expire after N seconds

  security:
    secret_scan: true                      # Scan for secrets before commits
    redact_tokens: true                    # Redact API tokens from logs

  # i18n & state mgmt are written for downstream skills to read
  i18n:
    active: <true|false>                   # Detected
    library: "<detected>"                  # angular-i18next | @ngx-translate/core | none
    pipe_name: "<detected>"                # I18NextPipe | TranslatePipe | null

  state_management:
    pattern: "<detected>"                  # signal-store | service-rxjs | static | none
    default_for_new_screens: "<detected>"  # What /sl-ds-plan should recommend by default
```

## Merge rules (Step 4)

When `.sl-ds-config.yaml` already exists:

1. **Read existing config** — parse YAML
2. **For each key in template:**
   - If absent in existing → add with detected/template value
   - If present in existing → leave untouched (user may have customized)
3. **For each key in existing NOT in template:**
   - Preserve as-is
   - Print a one-line note: `Preserved unknown key: <path>`
4. **Always update these (overwrite if present):**
   - `sl-ds-agents.version` — to current schema version
   - `sl-ds-agents.framework` — to detected
   - `sl-ds-agents.project.nx_enabled` — to detected
   - `sl-ds-agents.project.target_scope` — to detected (asks if mismatch with existing)
   - `sl-ds-agents.i18n.*` — to detected
   - `sl-ds-agents.state_management.pattern` — to detected (asks if mismatch with `default_for_new_screens`)

## Sensitive keys

Never auto-modify these (always ask user if they need changing):
- `sl-ds-agents.pipeline.mode`
- `sl-ds-agents.quality.*`
- `sl-ds-agents.accessibility.standard`
- Anything the user has added that's not in the template

## YAML validation

After writing:

```bash
node -e "require('js-yaml').load(require('fs').readFileSync('.sl-ds-config.yaml','utf8'))" 2>&1 \
  || (echo "Invalid YAML"; mv .sl-ds-config.yaml .sl-ds-config.yaml.invalid; exit 1)
```

If `js-yaml` not available, use a minimal `node -e "require('yaml').parse(...)"` check, or skip validation with a warning.

## Custom mode adaptation

If `dsMode: "custom"` was chosen in Step 3 (no SLDS installed):

- Comment out `slds_version` key (don't omit — keep as commented placeholder)
- Set `quality.groups.ds_maintainability.weight: 0` (no DS to maintain)
- Set `theme: null`
- Print warning: "Custom mode — DS components unavailable. `/sl-ds-implement` will produce plain CSS."
