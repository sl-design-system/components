## Button

**Node ID:** 5368:8591

Usage
-----

1.  **Large** is a default size of the button. The small size can be used in some specific cases when the large one is too big.
2.  The button width depends on its label.
3.  The button can't lead to another page — use the [link](https://styleguide.itsbuild.net/assets/Navigation/Link/v1/) instead.
4.  **Truncate** button's label if it doesn’t fit. Button label should never wrap. Avoid such long labels and translations. Truncating is a way to handle exception cases, but in the end the copy has to be updated.

Loading
-------

The button can be in the loading state: the button text is hidden and a spinner is shown in its place. Maintain the width that it would have if the text were visible. For examples, see the Styleguide.

Row of actions
--------------

1.  The distance between actions is defined in the variable **actions-gap**.
2.  The behaviour of a row of actions is handled by the [ButtonGroup](https://styleguide.itsbuild.net/assets/inputs/ButtonGroup/v1/) component. We don't have any analogue in Figma, for designers it is simple row inside an Auto Layout. Feel free to the refer to the ButtonGroup component in communication with developers.

**Documentation:**

- [https://styleguide.itsbuild.net/assets/inputs/Button/v1/](https://styleguide.itsbuild.net/assets/inputs/Button/v1/)

## Standalone link

**Node ID:** 5483:11186

Usage
-----

1.  A link is used for navigation only. It can't trigger any actions in a page.
2.  There are 2 types of links: inline and standalone. This component represents **only the standalone version**. Please use text styles and color variables to create an inline link.

Accessibility
-------------

A standalone link should not be confused with a button. They can't have the same styling.

For designers, it’s often difficult to define whether something is a link or a button before implementation — if you are not sure, please contact ALY team.

Primary link
------------

In some cases, the main action on the page navigates to a new page, so it can't be a button — use the Primary standalone link to create the visual hierarchy.

**Don't change or hide the arrow icon** in the Primary link. t is always the same since it’s an affordance. Other icons are not allowed.

Dark theme
----------

Some variants of the link component have a dark theme. See the Styleguide for more details.

Row of actions
--------------

1.  The distance between actions is defined in the variable **actions-gap**.
2.  The behaviour of a row of actions is handled by the [ButtonGroup](https://styleguide.itsbuild.net/assets/inputs/ButtonGroup/v1/) component. We don't have any analogue in Figma, for designers it is simple row inside an Auto Layout. Feel free to the refer to the ButtonGroup component in communication with developers.

## 🛠️ Row

**Node ID:** 4088:16314

Usage
-----

1.  This is a template component — please detach it before using as a starting point for your mockups. Don't worry, actual styles are at the level of Cells, so if the table style changes in the future, your mockups will be updated.
2.  Once detached, make a new, local component out of it. It keeps the shared styles connected but the content of your table is completely independent and nothing from outside would be able to break it. You may have as many local row components as you need.
3.  Adjust the number of columns in the local row component. You can change the type of content to one of predefined ones, or create something new. It is recommended to change text in the text cell to the name of the column.
4.  Put as many instances of your local row component as you need to the List template. A row takes the full available width.
5.  To create a table header row, select all cells inside the 1st row instance in a list and toggle the "Header" parameter.

Keywords
--------

Template, blueprint

## Heading

**Node ID:** 4224:9736

1.  <h1> describes the page as a whole and is typically only one per page.
2.  Avoid skipping heading ranks: e.g. make sure that a <h2> is not followed directly by an <h4>.
3.  Do not select heading levels based on their appearance. Select the appropriate heading based on its rank in your hierarchy.
4.  Do not overuse headings. In most cases, you will not need more than <h2> and the occasional <h3>.
