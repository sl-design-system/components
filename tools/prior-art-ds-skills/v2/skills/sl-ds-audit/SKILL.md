# DS Audit — Read-Only Compliance Check

## Purpose

A health check without side effects. Tells you: does the code match the verified tokens? Does it follow framework rules? Are DS imports complete? Has Figma drifted from cache? `/sl-ds-audit` never modifies anything — its output is a report, classified by severity, that informs whether you need `/sl-ds-update` (Figma drifted), `/sl-ds-implement --force` (code drifted from cache), or nothing at all. Useful before review, before release, or after a colleague hand-edited the code.

## When to use

- Before merging a PR that touched DS code
- Periodically (e.g. weekly) to detect silent drift
- After a colleague hand-edited code generated by `/sl-ds-implement`
- User just wants reassurance that things are OK without committing to any changes
- `/sl-ds` router routed here from `completed-fresh` state

## When NOT to use

- User wants to FIX issues — audit only reports, doesn't fix
- Code hasn't been generated yet — there's nothing to audit
- Pipeline failed mid-flow — `/sl-ds-verify` is the better tool for "did the build work?"
- Want a full visual diff against Figma — that's `/sl-ds-verify` with geometric pass; this skill does it as an option only

## Preconditions

| Required artifact | If missing |
|---|---|
| `.sl-ds-config.yaml` | STOP per [`../_shared/refusal-protocol.md`](../_shared/refusal-protocol.md) §4.7 (producer: `/sl-ds-setup`) |
| `.sl-ds-cache/sl-ds-impl/tokens-verified.json` | STOP per §4.7 (producer: `/sl-ds-tokens`) |

Code files don't strictly need to exist — if they don't, the audit reports that the screen exists in decisions but no code is present (interesting finding in itself).

## Inputs

**`$ARGUMENTS` (user-provided):**

| Field | Required | Description |
|---|---|---|
| `screenName` | no | Defaults to value in `pipeline-state.json` |
| `--check-figma` | no | Include Figma staleness check (1 extra Figma call); default: skip |
| `--check-geometric` | no | Include dev-server-based geometric check (delegates to `/sl-ds-verify --skip-build`); default: skip |
| `--severity=<level>` | no | Filter report to ≥ this severity (`critical`/`major`/`minor`/`info`); default: all |

## Workflow

**Pre-flight:** scope fe-standards per [`../_shared/fe-standards-index.md`](../_shared/fe-standards-index.md) §3 (per frontmatter `fe_standards_consulted` — full AP-1..18 + CHK-3 + A11Y-1..4 + PERF-1..4 + SEC-1..4 + I18N-1..5 + NG-1/NG-7/NG-8 + SDS-1..7). Code-scanner sub-agent (Step 2, `subagent_type: Explore`) loads ALL referenced files in clean context — justified because audit is comprehensive by design and sub-agent context is dedicated. Record `findings + appliedRules` in `audit-report.json` per `@_shared/cache-schema.md §8.8`.

### Step 1: Locate the audit scope

**Executor:** orchestrator on **sonnet**

```bash
SCREEN=$(jq -r '.screen' .sl-ds-cache/sl-ds-impl/pipeline-state.json 2>/dev/null || echo "")
TGT=$(yq -r '.sl-ds-agents.project.target_scope' .sl-ds-config.yaml)
AUDIT_PATH="${TGT}/src/app/features/${SCREEN}"  # or wherever /sl-ds-plan decided

test -d "$AUDIT_PATH" || WARN="Code directory not found at $AUDIT_PATH — audit will be incomplete"
```

If `$AUDIT_PATH` missing → still proceed (we'll audit cache-vs-Figma but no code-vs-cache).

### Step 2: Spawn code-scanner sub-agent

**Executor:** `Agent(subagent_type: "general-purpose", model: "sonnet")` — code-scanner sub-agent, clean context

Pass:
- `AUDIT_PATH`
- Paths to `tokens-verified.json`, `component-map.json` (if exists), `icons.json`
- Reference to [`references/audit-checklist.md`](references/audit-checklist.md)
- Reference to [`../../standards/fe/angular.md`](../../standards/fe/angular.md) (NG-*) + [`../../standards/fe/sanoma-ds.md`](../../standards/fe/sanoma-ds.md) (SDS-*) + [`../../standards/fe/antipatterns.md`](../../standards/fe/antipatterns.md) (AP-*)

Sub-agent runs all checks in [`references/audit-checklist.md`](references/audit-checklist.md). Returns findings array. Before returning, the sub-agent MUST apply the architectural exceptions suppression algorithm from §8.5 — parse `context/foundation/sl-ds-decisions/<screen>.md` `## Architectural exceptions`, suppress matching findings to `info` severity with `suppressedBy` tagging.

### Step 3: Optional — Figma staleness check

If `--check-figma`:

**Executor:** `Agent(subagent_type: "general-purpose", model: "haiku")` — figma-staleness-checker sub-agent, clean context

Pass: cached `figmaUrl` and `figmaLastModified`.

Sub-agent calls `get_metadata` on the URL, compares `lastModified`. Returns:

```json
{
  "cachedLastModified": "2026-06-08T10:00:00Z",
  "currentLastModified": "2026-06-15T10:00:00Z",
  "drifted": true,
  "daysSinceCache": 7
}
```

If drifted → add a finding of severity `major`: "Figma file modified since cache. Run /sl-ds-update to reconcile."

### Step 4: Optional — Geometric check

If `--check-geometric`:

Delegate to `/sl-ds-verify --skip-build --skip-lint` (skill orchestrator invokes the skill via Skill tool, passing flags). Outcome is added to the audit report as findings.

This is expensive (starts dev server) — only run when explicitly requested.

### Step 5: Compile audit report

**Executor:** orchestrator on **sonnet**

Aggregate findings from all sub-agents. Each finding has:

```json
{
  "severity": "critical" | "major" | "minor" | "info",
  "category": "tokens" | "fe-standards" | "sl-ds-imports" | "drift" | "accessibility" | "documentation",
  "rule": "no-hardcoded-tokens",
  "file": "features/teacher-dashboard/components/max-hero-section.scss",
  "line": 42,
  "message": "Hardcoded color #0a6165 — matches token color/foreground/primary/bold. Use var(--color-foreground-primary-bold).",
  "suggestion": "Replace `color: #0a6165;` with `color: var(--color-foreground-primary-bold);`",
  "fixable": true
}
```

**Severity rules:**
- `critical` — code WILL break (e.g. missing DS import for used `sl-*` tag in production)
- `major` — visible bug or significant drift (hardcoded token where one exists; Figma drifted; CUSTOM_ELEMENTS_SCHEMA undocumented)
- `minor` — best-practice violation (missing aria-label on icon-only button)
- `info` — observation worth noting (e.g. "Figma cache is 14 days old; consider refresh")

> 🔴 **[drift] Figma file modified 7 days ago since cache** — Run /sl-ds-update to reconcile. _Fixable by /sl-ds-update_

### Step 7: Write audit-report.json

Write per [`@_shared/cache-schema.md`](../_shared/cache-schema.md) §8.8 (envelope with `screen`, `scope`, `checks` status flags, `summary` (critical/major/minor/info/suppressed counts), `findings[]` with per-finding `suppressedBy` + `originalSeverity` from §8.5 exception suppression, `suggestedSkills`).

## Outputs

| Path | Purpose |
|---|---|
| `.sl-ds-cache/sl-ds-impl/audit-report.json` | Full machine-readable report with all findings |

**No code modifications.** No commits. No `.sl-ds-cache/` changes except writing the report.

## Hard gates

None — `/sl-ds-audit` is read-only and reports its findings. It never fails the way `/sl-ds-verify` does. The closest to a "gate" is severity = `critical` count > 0, which the user is told about loudly but is not blocked by the skill itself.

Sub-agent errors (e.g. code-scanner can't read a file due to permissions) → add as `info` finding ("Could not read X"), continue.

## Resume

_N/A — read-only inspection. Each invocation produces a fresh `audit-report.json`; partial runs are not resumed (audit is cheap to re-run from scratch)._

If a prior `audit-report.json` is older than `tokens-verified.json` → it's stale; regenerate.

## Next

After the report:

- **If critical/major findings exist:** suggested skills printed in summary (typically `/sl-ds-update` or `/sl-ds-implement --force`)
- **If only minor/info:** no automatic next; user decides
- **No findings:** skill returns success; nothing to do; user can proceed with confidence
